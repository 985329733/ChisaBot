# ADR-0004：密钥保险箱——机器人能用、看不到

- 状态：已采纳
- 日期：2026-10-14
- 相关：DESIGN.md §52、§53；docs/vault.md、docs/github.md

## 背景

Hark parity 第 3 项。机器人需要调用带密钥的接口，但密钥不能进模型上下文、聊天记录或日志；曾有机器人自己拼了一个输入令牌的
HTML 页面，必须杜绝。

## 决定

- 密钥存 `chisabot_vault_secrets`，值用部署的 `KEY_ENCRYPTION_KEY`（AES-GCM）加密，列表只显示末四位。
- 用户输入只走聊天里的**安全输入卡片**（`vault_request_secret`）：值直接 POST 到服务器，模型只知道「存好了 / 取消了」。
  IM、后台任务、routines 等非网页回合拒绝并指向设置页。
- 使用只走 `api_request`：https、`{{secret:名字}}` 在服务器替换，只发往该密钥绑定的域名，不跟随重定向，响应里把值抹掉。
- 网站登录不进保险箱，继续用「账号连接」+ 浏览器里的登录卡片。
- 保留名字（如 `github`）由对应功能管理，`api_request` / 输入卡片拒绝它们，防止绕过写操作确认。

## 后果

- 换 `KEY_ENCRYPTION_KEY` 会让所有密钥失效（需要重新输入）。
- 每个新集成优先复用保险箱，而不是各存各的令牌。
