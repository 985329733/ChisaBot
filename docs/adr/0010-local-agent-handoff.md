# ADR-0010：本地 agent 按任务交接；权限档位只收紧，「完全访问」就是设备的完全访问开关

- 状态：已采纳
- 日期：2026-10-15
- 相关：ADR-0003、ADR-0009；DESIGN.md §66；docs/local-agents.md；BACKLOG CB-007、CB-008

## 背景

用户（2026-10-15 00:25）：「做。但是本地pc的需要一些权限控制和沙盒之类的问题，以及agent选择…本地不安装agent，让云端的agent控制本地也可以吧？」
ADR-0003 留了一个开口：「机器人可以选择由某台设备上的某个本地 agent 回答」。同时 #119（ADR-0009）上线了设备的「完全访问」开关。

## 决定

- **默认不变**：云端机器人用 `device_*` 工具操作电脑，电脑上什么 agent 都不用装。
- **本地 agent 是按任务交接，不是换掉机器人**：机器人调用 `device_agent_run` 把一整件活儿交给电脑上的 Claude Code / Codex CLI /
  OpenCode / Gemini CLI / Aider 或 ChisaBot 内置循环；进度、停止、改动审阅在聊天里的任务卡片上，结果回到同一段对话，
  机器人再总结。每台电脑有一个默认 agent（设置 → 设备 → 本地 agent），聊天里可以点名（「用 Claude Code …」）。
  不做「整个机器人改由本地 agent 回答」：记忆、技能、审批、渠道都在服务器上，换掉回答者会让它们全部失效。
- **权限档位**（每台设备）：只读 / 工作区（存下来的两档）+ 完全访问。档位挂在设备 hub 上，**只收紧**：档位之外的操作即使能力是
  「允许」也改成审批，「关闭」照旧关闭。任务可以要求更严的档位，不能更宽。只有用户能改档位，机器人没有工具。
- **「完全访问」档位 = ADR-0009 的完全访问开关**，不另设一个永久档位：开着时实际档位是完全访问（不收紧、本地 agent 任务不要批准、
  CLI agent 可以跳过它自己的逐条确认），到期 / 关闭 / 急停后回到存的档位。避免两个「完全访问」语义不一致、一个有时限一个没有。
- **隔离**：默认 git worktree（不是 git 仓库时退成临时副本），改动要用户在卡片上点「应用改动」才回到原文件夹；有系统级沙盒时可选
  bubblewrap（Linux）/ sandbox-exec（macOS）/ Docker·Podman（仅内置 agent）/ WSL。一次性副本不是安全沙盒，所以在副本里
  Claude Code 不跳过确认；只有完全访问或系统级沙盒里才 `--dangerously-skip-permissions`（root 时 `IS_SANDBOX=1`）。
- CLI agent 用它自己登录的账号，ChisaBot 不碰其凭据；内置循环默认由服务器代调机器人的模型（密钥不出服务器），也可配本地模型。

## 取舍

- 按任务交接比「绑定回答者」少一个概念、和聊天卡片 / 审批天然契合；代价是本地 agent 看不到聊天上下文，机器人要写完整指令。
- 档位只收紧不放宽：实现简单、和能力开关 / 审批偏好不冲突（优先级：关闭 > 档位之外 → 询问 > 能力设置；完全访问开着时全部允许）。

## 后果

- PC 客户端和服务器节点（chisabot-node）都带本地 agent 运行时；旧客户端收不到检测结果，设置页如实显示「还没检测过」。
- 真机（Windows / macOS）上的 CLI agent 与沙盒还没验证（CB-017）。
