# ADR-0003：默认「云端 agent + 设备节点」，本地 agent 运行时可选

- 状态：已采纳（本地 agent 部分在做：BACKLOG CB-007 / CB-008）
- 日期：2026-10-15
- 相关：docs/architecture.md §2.1、§2.5；docs/pc-node.md

## 背景

用户的核心诉求（2026-10-15）：在任何地方管理所有设备，包括本地电脑；云端机器人能读、改、写本地文件和代码；希望能像本地
OpenClaw / Hermes 一样给「完全权限」，同时有权限控制 / 沙箱，并且能选 agent（用户对本地 agent 运行时说「做」）。

## 决定

- **默认**：agent 循环跑在服务器上（模型、记忆、技能、保险箱、审批都在服务器），设备只是执行节点，通过出站 WSS 连到服务器，
  按能力权限执行 `device_*` 操作。
- **可选**：设备上登记本地 agent 运行时，机器人可以选择由某台设备上的某个本地 agent 回答；输出仍走同一套聊天流、卡片、停止语义。
- 权限在服务器强制执行并写审计；「完全访问」是一个显式的设备级模式，有风险确认和急停。

## 后果

- 手机 / 网页随时可用，电脑离线时机器人仍能做云端的事，并如实说明电脑离线。
- 云端 agent 碰本地文件要经过网络往返；大仓库的编码体验依赖设备侧工具做得够「粗」（搜索、精确替换、跑测试）。
- 本地 agent 带来第二套执行环境，需要配置档统一权限。

## 考虑过的其他方案

- 只做本地 agent（像 OpenClaw）：手机 / 网页端失去能力，记忆、技能分散在每台电脑上。
- 只做云端 agent：本地编码体验受限，用户明确要可选的本地 agent。
