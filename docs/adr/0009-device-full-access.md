# ADR-0009：设备「完全访问」——一个有时限、只能主人打开的总开关

- 状态：已采纳
- 日期：2026-10-15
- 相关：DESIGN.md §XX、§16、§45、§58；docs/pc-node.md §12–§14；BACKLOG CB-006；列 `devices.full_access_until`

## 背景

用户（2026-10-15 00:18 / 00:22）：在任何地方管理所有设备，云端机器人能读、改、写本地代码；PC「像本地 OpenClaw / Hermes
那样有更多权限」，同时保留权限控制。默认的逐项能力（关闭 / 询问 / 允许）+ 允许的文件夹 + 每次审批，对「让机器人在我电脑上
连续干一小时活」来说太碎：一次编码循环要点几十次「允许」。

## 决定

- 每台设备一个**完全访问**开关，有效期 1 小时 / 24 小时 / 永久；存为 `devices.full_access_until`（可空 timestamptz，开机
  `ADD COLUMN IF NOT EXISTS`，旧镜像忽略，可直接回滚）。「永久」= 9999 年。
- 打开期间：所有能力视为「允许」、不再弹审批（包括 §58 的聊天确认卡片和本机高危确认）、不限文件夹、后台命令不受 10 分钟上限、
  可以 `elevated: true`（Windows 一次 UAC；Linux / macOS 需要 root 或免密 sudo）。`git push` 在非完全访问时总是询问。
- **只有设备主人在网页上能打开**；机器人没有任何工具能改设备设置；设备端只能把它关掉（PC 打开时还要本机确认一次，拒绝 = 关掉）。
- 紧急停止（网页、PC 托盘、手机）同时关闭完全访问；到期由服务器定时器关闭并通知设备。
- 审计照常：每个操作照样写 `device_audit_events`，开 / 关本身也记一条。

## 取舍

- 选「总开关 + 时限」而不是再加一档能力：用户要的是一个明确的模式切换，到期自动回到「询问」，忘了关也不会一直敞开。
- 不做沙箱：完全访问本来就是「整台机器」；需要隔离的场景用服务器节点跑在容器 / 独立用户里（docs/pc-node.md §14）。
- 风险：模型误操作可以删文件、推代码。缓解：默认关、有时限、全程审计、急停一键、`edit_file` 改前备份。

## 后果

- 机器人在完全访问的设备上可以不打断地完成「搜索 → 读 → 改 → 跑测试 → 提交」的循环。
- 将来如需「按机器人」限制完全访问（只给某个机器人），另开 ADR（参见 ADR-0002）。
