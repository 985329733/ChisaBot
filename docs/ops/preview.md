# 预览与测试环境

[← 运维手册总览](README.md)

测试分层、回归套件清单、已知不稳定测试见 [testing.md](../testing.md)。本页讲**在服务器上怎么搭测试环境、怎么在生产上安全地检查**。

## 1. 预览容器

需要写数据的端到端一律在预览容器里跑，不在生产上：

- **镜像**：生产镜像或分支构建的镜像。
- **数据**：生产数据库的副本（`pg_dump` → 恢复到预览容器自己的卷）。副本里有真实用户数据，按生产数据对待，用完删除。
- **端口**：`127.0.0.1:<端口>`，每个人 / 每个功能用自己的端口段（例如 31xx–32xx）和容器名（`cb-<功能>-preview`），互不冲突。
- **出网封锁**：给预览容器一个独立网络，用 iptables 拒绝出网（只放行假模型 / 假服务），保证预览里的机器人不会真的发消息、调第三方。
- **假模型**：OpenAI 兼容的 mock（`tests/chat-scroll/mock-model.mjs`），容器名例如 `cb<功能>-mock`。
- **一个预览容器只跑一轮端到端**，下一轮重建（Bun SQL 连接错位问题，见 [incidents.md](incidents.md) §1）。
- **跑完拆掉**：容器、卷、临时网络、拷进去的源码和数据库副本。

建议把这些步骤写成一组脚本放在 `/opt/chisabot-ops/<功能>/`：`setup-preview.sh`（建网络 / 恢复副本 / 起容器）、`preview.sh`（跑测试）、
`teardown.sh`（拆除）。

**可交互原型**（给别人点着试的）也用同样的隔离：数据副本 + 出网封锁 + 自己的端口。不再需要时及时拆掉，并删除它占用的镜像。

## 2. 浏览器测试

- playwright-core + 镜像里的 Chromium。
- 最低覆盖：宽 1280 亮色 + 窄 390 暗色；涉及布局的加 900 / 1440。
- 改到聊天 / 同步 / 滚动：`tests/chat-scroll/regression.sh`，需要一段长对话复制到预览里的一次性机器人。
- 本地构建的镜像上 chat-scroll 偶发 1–2 项跳动：先用同样方式构建的 main 对照，再判断是不是改动引起的。

## 3. 生产测试守则

1. **绝不删除已有的机器人 / 对话**。测试只用一次性机器人（标题例如「临时测试（会删除）」），删除只走带快照的守卫脚本：
   开始前快照现有机器人 id → 只记录本次创建的 → 只删记录过的。
2. **前后快照**：线程数、机器人数、设备数、用户数、关键设置哈希，打印机器人 id 和线程 id；除镜像 / 版本外必须一致。
3. **设备相关的 e2e** 用一次性节点容器配对，跑完 `DELETE /api/devices/<id>`；不在生产上配对 / 解绑真实手机或电脑。
4. 自测模型用 `POST /api/admin/smoke`，不用真实对话。

## 4. 生产只读检查

1. 临时签发一个会话（写入网关会话库，绑定内置管理员——`user_id IS NULL` 的那一类会话），记下令牌。
2. playwright 打开页面，**拦截所有非 GET 请求**（本地返回 204），有副作用的 GET（例如第一次读收藏夹会写入种子数据、`/api/computers/*`）
   也在本地伪造，WebSocket 本地关闭。
3. 断言页面 / 接口。
4. **删除会话**。

已知假象：冷启动的第一个浏览器上下文可能发两次 connect，被拦截后对话显示为空，不代表生产有问题。

## 5. 性能检查（可选）

上线后可以对生产做只读的性能采样（首屏、打开长对话、切换机器人的耗时），同样用临时会话 + 拦截写请求。和上一版的数据对比，
退化超过阈值就回滚或开 issue。
